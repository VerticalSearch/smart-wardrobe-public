# 智能衣橱方案介绍（当前正式方案）

本文按当前确认后的正式方案整理，不再沿用旧的 `K230 + 串口屏` 主线口径。

## 1. 一句话方案

当前系统主线为：

`树莓派触摸屏网页 + 树莓派外接摄像头 -> 云端后端 -> 树莓派串口 -> STM32F407 主板1 -> STM32F407 主板2 -> 机构执行`

## 2. 当前系统由哪些部分组成

- 树莓派 + 触摸屏：
  现场主 HMI，在树莓派浏览器里运行网页，负责接收用户点击操作。
- 树莓派外接摄像头：
  负责拍照采集衣物图片，并由树莓派上传到云端。
- 云端后端：
  负责衣物数据管理、识别结果保存、任务生成和状态同步。
- STM32F407 主板1：
  负责流程协调、串口桥接、传感器数据汇聚和任务判定。
- STM32F407 主板2：
  负责步进电机、舵机、伸缩轴、夹爪、毛刷、热风机等执行动作。
- 执行机构：
  包括夹爪、导轨、伸缩机构、处理区 B 毛刷、存储区 C 热风机 / 负离子 / 风扇等。

## 3. 每个模块的职责

### 3.1 树莓派

树莓派在当前方案里承担三件事：

1. 运行现场触摸屏网页。
2. 控制外接摄像头拍照。
3. 通过串口与主板1通信，完成上层任务与底层执行链路的衔接。

树莓派不直接做电机执行，不直接承担主板级实时控制。

### 3.2 云端后端

云端负责：

- 衣物列表管理
- 图片上传接收
- 衣物识别结果保存
- 任务生成与状态同步
- 上身效果预览和推荐类能力

云端是数据与任务中枢，不直接控制硬件串口。

### 3.3 主板1

主板1是系统调度中枢，当前重点职责是：

- 接收树莓派串口指令
- 汇聚本地传感器数据
- 参与任务判定和流程控制
- 向主板2转发执行命令
- 管理本地状态显示和异常处理

主板1接收的重要输入包括：

- 除湿袋重力传感器
- 温湿度传感器
- 挂位限位开关点位检测
- 本地按键和状态量

### 3.4 主板2

主板2是执行核心，负责：

- 多轴步进电机动作
- 舵机动作
- 伸缩轴、夹爪和移动机构动作
- B 区毛刷清理动作
- C 区热风机、负离子、通风风扇等护理动作

主板2只负责动作落地，不负责视觉和云端通信。

## 4. 当前流程怎么跑

### 4.1 入库流程

1. 用户放入衣物。
2. 树莓派控制外接摄像头拍照。
3. 树莓派上传图片到云端。
4. 云端识别衣物并建档。
5. 前端刷新衣物列表。

### 4.2 取衣流程

1. 用户在树莓派触摸屏网页上点击取衣。
2. 网页把控制意图发送到云端。
3. 云端生成任务。
4. 树莓派通过串口把控制信息送到主板1。
5. 主板1结合限位、温湿度、重力等状态做条件判断。
6. 主板1向主板2下发动作命令。
7. 主板2驱动机构完成取衣。
8. 状态回写到云端和前端。

### 4.3 清理与护理流程

- 处理区 B：毛刷清理衣物表面附着毛发。
- 存储区 C：热风机、负离子和风扇完成护理。
- 主板1负责调度，主板2负责执行。

## 5. 当前方案的特点

这套系统最核心的不是“会拍照”或“会取衣”，而是：

- 前端、云端、控制板、执行机构已经串成完整链路
- 电控部分采用双 STM32F407 分层控制
- 主板1具备多传感器数据汇聚与状态判定能力
- 主板2聚焦实时运动控制与机构执行
- 系统具备感知、判定、调度、执行、回写的闭环逻辑

## 6. 与旧方案的边界

以下内容不再属于当前正式主线：

- K230 作为视觉与联网核心
- 串口屏作为现场主交互入口

这两部分现在都只作为历史资料保留，不应在当前答辩或方案说明中继续作为主方案描述。
