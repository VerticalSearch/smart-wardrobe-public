# 智裳序功能达成度与完善方案

生成时间：2026-06-05

本文按当前项目文件、树莓派网关、双 STM32 固件和最近改动记录，对路演稿中的功能进行落地核对，并给出补齐方案。结论口径：当前系统已经具备“树莓派触摸屏网页 + 串口网关 + 双 STM32 动作流程 + 部分护理控制 + 衣物列表/AI 页面”的演示基础，但还不能按完整产品口径宣称所有功能已经闭环实现。建议将比赛展示分成“已实现可演示”“正在联调”“后续完善”三类，避免评委追问时出现代码与表述不一致。

## 一、总体现状结论

当前可以支撑的演示闭环：

- 树莓派本地网关运行网页，页面可显示衣物列表、存衣/取衣/AI 推荐/护理页面。
- 网页通过 `/api/control` 向主板1发送 K230 兼容串口协议：`@ACMD`、`@MCMD`、`@SCMD`、`@OCMD`。
- `@ACMD|6|...` 可进入主板2自动放衣流程；`@ACMD|7|...` 可进入主板2自动取衣流程；`@ACMD|8/9|...` 可触发主板1热风移动启动/停止。
- 主板2中已有自动放衣、自动取衣动作列表和刷毛动作 10；主板1中已有热风移动电机、紫外灯、通风风扇、HX711 两路称重读取与护理页上报相关代码。
- 树莓派网关具备 USB 摄像头拍照上传接口、云端 API 代理、串口日志和状态接口。

当前不能完整支撑的产品级闭环：

- “AI Agent 自动拆解任务下发硬件”还主要是页面/API 概念与按钮联动，缺少可验证的 Agent 决策流程、任务状态机和失败恢复。
- “无标签自动建档”依赖云端识别接口，但当前工作区没有后端源码；只能证明前端和树莓派具备上传入口，不能证明识别字段稳定生成。
- “正反面多角度采集”在主板2动作列表里有拍照请求/补光相关接口迹象，但没有完整证明已联通树莓派摄像头、云端入库和状态回写。
- “路径防干涉规划、限位坐标反馈、动态库存位置闭环”尚未从当前代码中看到完整落地；目前更像预设动作列表，不是根据衣物位置实时规划。
- “负离子发生器”页面有按钮，但主板1 `@OCMD` 当前只明确支持 `uv_lamp` 和 `vent_fan`，`ionizer` 还需要补继电器映射和硬件验证。
- “温湿度全天候调控”没有在当前固件和树莓派页面中形成稳定闭环；当前更明确的是 HX711 干燥袋状态和部分继电器控制。
- HX711 单位口径已统一为 counts：当前主板1通过 `@CARE|left=...|right=...` 上报的是去皮后的 HX711 原始净值，树莓派护理页默认按 counts 展示；未用已知重量标定前，不写成 kg/kPa。

## 二、功能达成度对照表

| 路演稿功能 | 当前达成度 | 当前依据 | 主要缺口 |
| --- | --- | --- | --- |
| 树莓派触摸屏 HMI | 已具备演示基础 | `raspberry_pi_gateway/static/cloud_display.html`、树莓派 `/cloud` 页面 | 需要保持开机自启动、页面缓存清理、现场截图验证流程 |
| 双 STM32 + 树莓派分层主控 | 已具备主链路 | 网关 `/api/control`，主板1 `UART3_PI_GATEWAY`，主板2 USART1 动作处理 | 需要现场串口日志、主板1/主板2状态回传展示 |
| 自动放衣 | 半闭环 | 网页任务下发 `@ACMD|6`，主板2 `Board2_ActionList_StartDefault()` | 需要实机连续跑通、限位/回零/卡滞保护和完成状态回传 |
| 自动取衣 | 半闭环 | 网页任务下发 `@ACMD|7`，主板2 `Board2_ActionList_StartTakeClothes()` | 需要选中衣物 ID 与实际挂位/坐标绑定，而不是只跑预设动作 |
| XYZ 三轴联动夹爪 | 部分具备 | 主板2多轴步进、舵机、动作列表存在 | 需要把“XYZ 坐标-衣物位置-动作序列”做成参数化表，而不是固定流程 |
| 暂存衣杆限位检测 | 不宜宣称已闭环 | 当前搜索未看到稳定“暂存衣杆限位坐标反馈”业务闭环 | 需要补限位输入、去抖、状态上报和前端显示 |
| 多角度/正反面采集 | 半闭环 | 树莓派有摄像头上传；主板2动作列表有拍照请求/补光接口迹象 | 需要补“正面拍照-翻转/移动-反面拍照-合并入库”的流程和数据结构 |
| 无 RFID 自动建档 | 半闭环 | 树莓派可上传图片，前端可显示云端衣物列表 | 云端识别后端源码不在当前项目，无法证明款式/颜色/材质/季节稳定生成 |
| AI 智能穿搭 | 半闭环 | 页面有 AI 推荐、全身照上传、推荐结果显示和确认出库按钮 | 需要真实 AI 服务、推荐解释、库存约束、任务拆解与失败处理 |
| AI Agent 自动拆解硬件任务 | 未完整实现 | 目前按钮直接映射动作码，非 Agent 动态规划 | 需要 Agent 生成任务计划，再由规则层校验成 `@ACMD/@MCMD/@SCMD` |
| 粘毛/刷毛 | 半闭环 | 主板2任务 10 有刷毛动作：舵机4 + 刷毛电机往复 | 需要页面常规入口、动作时长可调、完成状态回传和实机验证 |
| 往复热风低温除湿 | 半闭环 | 主板1热风移动任务 8/9 和风扇/热风移动电机代码存在 | 需要温控闭环、热风温度传感、防过热保护和护理流程计时 |
| 紫外线杀菌 | 部分可控 | 主板1支持 `uv_lamp` 输出，页面有开关 | 需要定时、门开关联锁、防误触发安全策略 |
| 负离子祛味 | 当前不闭环 | 页面有按钮，但主板1输出映射未支持 `ionizer` | 需要新增继电器通道、协议映射、硬件接线和验证 |
| 通风/环境管理 | 部分可控 | 主板1支持 `vent_fan` 输出 | 需要温湿度采集、自动阈值控制、状态上报 |
| 干燥袋重力监测 | 半闭环 | HX711 两路读取、护理页曲线、`@CARE` 上报 | 需要统一 counts/kg 口径，用已知重量标定，定义“饱和阈值” |
| 急停保护 | 部分具备 | 网关协议支持 emergency，主板2 action 0 停止动作 | 需要在 `/cloud` 常规页面显式放急停按钮，并实机验证全轴停机 |
| 手机 APP 双端 | 不宜宣称当前已闭环 | 项目口径提到 App/Web，但当前主要验证是树莓派网页 | 需要 App 接口、登录/鉴权、任务同步和状态一致性 |
| 多场景产品化 | 方案层成立 | 模块化设计可作为规划 | 需要结构尺寸、线束、电控箱、安全认证和 BOM 成本核算 |

## 三、优先补齐路线

### 第一阶段：把“现场演示闭环”做稳

目标：比赛现场能稳定演示“点按钮-主板动作-页面有状态”。

1. 固化树莓派开机自启动。
   - 默认启动 `/home/pi/raspberry_pi_gateway/run.py`。
   - Chromium 使用独立 profile 打开 `http://127.0.0.1:8000/cloud?ts=...`。
   - 保留 `grim` 截图验证流程，避免浏览器停在旧缓存或本地文件。

2. 补齐任务按钮到状态反馈。
   - `发起新入库` 下发 `@ACMD|6|...` 后，主板1回传 `@DBG1` 或新增 `@TASK|store-new|running/done/error`。
   - `确认取衣` 下发 `@ACMD|7|...` 后，主板2完成时通过主板1回传完成状态。
   - 页面不要只显示“已加入队列”，要显示“串口已下发、主板1已收到、主板2执行中、完成/异常”。

3. 增加 `/cloud` 常驻急停。
   - 页面顶部增加急停按钮。
   - 下发 `/api/control {action:"emergency"}`。
   - 主板1转发停止，主板2停止动作队列并失能轴。

4. 统一 HX711 展示口径。
   - 当前默认口径固定为“去皮后的 HX711 counts，用于判断干燥袋变化趋势”。
   - 如果要说 kg，必须用已知重量做两路标定，得到 counts/kg 后再修改主板1和树莓派页面共同输出 kg。
   - 如果要说 kPa，还需要在 kg 标定基础上明确受力面积，再换算压力；未完成前不默认展示 kPa。

### 第二阶段：把“存取动作”从预设流程升级为可解释流程

目标：评委问“你怎么知道取哪件衣服”时，有可讲清楚的逻辑。

1. 建立挂位表。
   - 云端衣物记录增加 `slot_id`、`zone`、`x/y/z` 或动作点位编号。
   - 前端显示衣物位置不只显示“位置：xx号仓”，还要能用于取衣动作参数。

2. 参数化主板2动作列表。
   - 当前任务 6/7 是固定动作入口。
   - 需要补“根据 slot_id 选择点位”的参数表，例如 `A01/A02/B01/C01` 对应 X/Y/Z/舵机/等待时间。
   - 树莓派下发可用 `@MCMD/@SCMD` 分步动作，或扩展 `@TASK|type|slot|id` 由主板2解析。

3. 增加限位与回零保护。
   - 每个关键轴配置回零方向、限位输入、超时。
   - 页面展示“已回零/运行中/限位触发/超时停止”。

### 第三阶段：补齐“视觉入库 + 无 RFID 数字建档”

目标：把“无标签自动建档”从概念变成可演示。

1. 树莓派摄像头链路稳定化。
   - 固定摄像头命令：`libcamera-still` 或 `fswebcam`。
   - `/api/status` 必须显示 camera ok。
   - 拍照失败要在页面显示明确错误。

2. 正反面采集流程。
   - 主板2动作流程中插入“请求拍照”节点。
   - 树莓派收到拍照请求后采集图片并返回结果。
   - 一件衣物至少保存 `front_image_url`、`back_image_url`、`thumbnail_url`。

3. 云端识别字段固定。
   - 后端 `POST /api/wardrobe/add` 返回固定结构：`id/name/category/color/material/season/style_tags/img/slot_id/status`。
   - 识别失败时生成“待人工确认”的临时卡片。

### 第四阶段：把 AI 推荐升级成 AI Agent

目标：路演中“AI Agent”有真实任务分解依据。

1. Agent 输入。
   - 用户场景、天气、库存衣物、最近使用记录、护理状态、衣物可用状态。

2. Agent 输出。
   - 推荐搭配：上衣/裤装/外套/鞋包配饰。
   - 解释理由：颜色、场景、温度、用户偏好。
   - 硬件计划：需要取出的 item_id 列表、slot_id 列表、任务顺序。

3. 规则校验层。
   - Agent 只能输出建议，不能直接发电机命令。
   - 本地规则层检查衣物是否在柜、机械是否空闲、是否急停、门是否关闭。
   - 校验通过后才下发 `fetch` 或 `@ACMD/@MCMD/@SCMD`。

### 第五阶段：完善护理与环境管理

目标：把“养护亮点”从可控按钮变成自动策略。

1. 紫外灯。
   - 增加定时任务、门开关联锁、倒计时显示。
   - 只允许无人/关门状态开启。

2. 热风除湿。
   - 增加温度采集和过温保护。
   - 明确低温阈值，例如 40 摄氏度以下。
   - 任务 8/9 之外增加完整“护理 15 分钟”流程。

3. 负离子。
   - 给主板1新增独立输出通道。
   - 网关 `normalize_output_device()` 和主板1 `board1_pi_gateway_parse_output_device()` 同步支持 `ionizer`。
   - 页面按钮再接真实硬件。

4. 干燥袋。
   - 两路 HX711 做砝码标定。
   - 定义 `空载值`、`正常吸水区间`、`更换阈值`。
   - 页面显示趋势和“建议更换”而不是只显示数值。

## 四、建议修改路演稿口径

建议把“已经全部实现”的表达改成“我们已经完成核心样机链路，并围绕 AI Agent 闭环做了功能集成”。更稳妥的表达如下：

> 目前样机已实现树莓派触摸屏控制、双 STM32 分层执行、自动存取动作入口、护理执行机构控制、衣物云端列表展示与 AI 推荐交互界面。针对无标签建档、AI Agent 决策和多传感器环境管理，我们已经完成接口与样机链路设计，后续将继续补齐正反面视觉采集、云端识别字段固化、任务状态回传和安全联锁，让系统从可演示样机升级为完整产品闭环。

答辩时可以这样分层回答：

- 已经能演示：触摸屏下发任务、主板1接收、主板2执行放衣/取衣预设流程、护理页显示、紫外/通风/热风移动控制。
- 正在完善：衣物 ID 与实际仓位绑定、状态回传、摄像头稳定采集、AI 推荐后自动取衣。
- 后续产品化：负离子通道、温湿度闭环、门锁/急停安全、kg 标定、App 双端同步。

## 五、推荐最近三天改造清单

### 第一天：修演示链路

- 给 `/cloud` 增加急停按钮。
- 点击 `发起新入库/确认取衣` 后显示串口下发结果和最近串口日志。
- DAP 或串口日志验证主板1收到 `@ACMD|6/7`。
- 主板2动作结束后至少回传一条“done”状态。

### 第二天：修护理亮点

- 保持 HX711 默认 counts 口径。
- 若无砝码标定，页面和讲稿全部使用“counts 趋势监测”，不要写 kg/kPa。
- 把负离子按钮改成“预留”或补真实继电器输出。
- 紫外灯加倒计时和安全提示。

### 第三天：修 AI 与建档展示

- 准备 6 到 8 件固定样例衣物，云端数据库提前录入完整字段。
- 摄像头若不稳定，准备“拍照上传成功”的备选演示视频或静态图片。
- AI 推荐至少返回真实 item_id，并能一键触发取衣动作码 7。
- 页面展示“AI 推荐理由 + 选中衣物 + 下发硬件任务”三段式过程。

## 六、当前最不建议硬讲的点

- 不建议说“已经实现全自动路径防干涉规划”，除非补齐点位表、限位、回零和异常处理演示。
- 不建议说“已经实现负离子祛味”，除非主板1真实接入并验证 `ionizer` 输出。
- 不建议说“干燥袋重量 kg 或压力 kPa 已精准显示”，除非完成砝码标定和受力面积换算；当前更适合说“HX711 counts 趋势监测”。
- 不建议说“AI Agent 已完全自动拆解机械任务”，当前更适合说“AI 推荐与硬件取衣链路已打通，Agent 规则校验层正在完善”。
- 不建议说“手机 APP 双端已完整闭环”，除非现场能展示 App 与云端/树莓派状态同步。
